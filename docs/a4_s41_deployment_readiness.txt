    db.sqlite3 - the A4 requirement Connor asked about

      Verified against a fresh `git clone` of main, not the local
      working copy, because that is what the grader and PythonAnywhere
      actually get:

        present in the clone : yes, 196608 bytes
        git check-ignore     : not ignored
        file type            : SQLite 3.x database
        pragma integrity_check: ok
        contents             : 7 datasets, 10 contracts, 12 runs,
                               9 violations, 6 users

      .gitignore has `*.local.sqlite3`, which matches the disposable
      db.local.sqlite3 used for screenshots and does NOT match
      db.sqlite3. There is no `db.sqlite3` or `*.sqlite3` rule. So the
      A4 sequencing note 1.2 requirement holds.

      Worth stating plainly for whoever tidies .gitignore before
      submission: committing a database is the opposite of normal
      practice, and A4 deliberately requires it. Do not "fix" this.

    requests==2.32.3 is pinned in requirements.txt.

    PythonAnywhere outbound network access

      Free PythonAnywhere accounts cannot reach arbitrary hosts - all
      outbound HTTP goes through a proxy and only allowlisted sites
      resolve. An external API that works locally can therefore fail on
      the deployed site, which would have cost Part 2 its marks there.

      Checked against https://www.pythonanywhere.com/whitelist/ :
      `openlibrary.org` IS on the allowlist (and so is
      covers.openlibrary.org). requests picks up the proxy from the
      environment variables PythonAnywhere sets, so no code change is
      needed.

      If the external API is ever swapped for another host, check that
      list again before assuming it will work deployed.

    Gap, not mine to close: /api/lookup/ has no tests. The suite is
    still 113, the same count as before Part 2 merged. The view's error
    handling (timeout=5, raise_for_status, 504 on Timeout, 502 on
    RequestException) reads correctly but nothing exercises it. Mocking
    requests.get with unittest.mock.patch would cover the success path
    and both failure paths without touching the network.
